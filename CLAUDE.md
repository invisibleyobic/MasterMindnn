# CLAUDE.md — правила работы над сайтом мастермайнда

Этот файл Claude читает в начале каждой сессии и сверяется с ним после каждого шага.
Подробности: `BRIEF_2026-10-12.md` (ТЗ заказчика), `POSITIONING.md` (позиционирование, было/стало), `AUDIT.md` (техника), `QUESTIONS.md` (открытые вопросы и ежедневник задач), `research/` (рынок и досье Рафаэля).

## 1. Главное правило: самопроверка после КАЖДОГО действия
После любой правки задать себе вопрос «работает ли?» и проверить фактом, а не на глаз:
1. Поднять локальный сервер (`python3 -m http.server 8765`) и прогнать Playwright (Chromium уже стоит в контейнере).
2. Ширины обязательно: **320, 360, 390, 430 (телефоны), 768 (планшет), 1440 (десктоп)**.
3. Проверить: нет горизонтального скролла; ни одно слово не рвётся посреди (у `.kin-word` ширина ≤ родителя);
   верх hero не уходит под шапку; нет JS-ошибок в консоли; каждое видео качается один раз.
4. Посмотреть скриншот глазами (мобила + десктоп).
5. Пока проверка не пройдена — результат заказчику НЕ показывать.

## 2. Критик (против «замыленного глаза»)
Перед сдачей крупного этапа запускать независимого субагента-критика.
Его роль: скептичный арт-директор + маркетолог продаж, который не видел, как делалась работа.
Он спорит, ищет слабые места в подаче, дизайне, текстах и конверсии, предлагает свою альтернативу.
Его замечания записываются в `POSITIONING.md` / `AUDIT.md` в раздел «Критик» вместе с решением: принято / отклонено и почему.
Субагента звать экономно: один прогон на этап, короткое задание, без пересказа всего контекста.

## 3. Формат ответов заказчику
- Обычный текст — для второстепенного.
- То, на что заказчик должен ответить или обратить внимание (вопросы, решения, риски) — **ЖИРНЫМ КАПСОМ** и/или заголовком `##`, чтобы не проморгать.
- Без антитез. Без выдумок: факты о Рафаэле, ссылки, цифры — только от заказчика или из существующих материалов.
- Тон дружеский, наставнический, без канцелярита и фраз «понял, брат», «отвечу честно, без воды».
- Варианты «А — быстрее / Б — экономнее по токенам» предлагать только на действительно тяжёлых задачах.

## 4. Технические правила проекта
- **v3 — три версии на выбор (текущий этап):** `a/`, `b/`, `c/` — в каждой 5 страниц: `index` (мастермайнд), `rafael`, `circles`, `codex`, `people`. Корневой `index.html` — страница выбора версии.
  A «Тёмная осень» (медь, Onest) · B «Клубный» (шампань, Manrope, «Медиа» НЕ выделяем) · C «Город и кино» (видео-облёт, Unbounded+Onest, красный логотипа только точечно, НЕ рыжий).
  Страницы НЕ правятся руками: тексты, данные, шапка/подвал, герои тем — в `tools/pages.py` → `python3 tools/pages.py` → коммит готовых `.html`.
  Стили: `css/site.css` (общая вёрстка) + `css/theme-a|b|c.css` (токены и герой темы). Скрипт `js/site.js`. Кэш: `V` в `tools/pages.py`.
  Шрифты тем пока с Google Fonts — после выбора темы перевести на свой хостинг.
- **Логотип:** `assets/brand/logo-{red,white,black,flat-draft}.svg` (знак из трёх блоков). В шапке — инлайн-SVG `.logo__mark`, цвет через `--logo`.
- Проверка скролла для скриншотов: пауза ≥150 мс на шаг, иначе блоки `.reveal` не успевают появиться (ложная «пустота»).
  Сезон ставится по дате (дек–фев — зима), проверка вручную: `?season=winter`.
- **v1 (архив):** `v1.html` + старые `css/*.css`, `js/*.js` (кроме site.*). Закрыт от индексации. Кэш-версия `?v=11`.
- Скрипт проверки v2: 5 страниц × 6 ширин, вылеты, 404, ошибки JS (Playwright, см. раздел 1).
- Видео: только пережатые. Фон — WebM (VP9) + MP4 (H.264) запасной, без звука, 720p, 25 fps, ≤ 2 МБ. Отзывы — MP4 H.264 720p, `+faststart`, грузятся только по клику.
- Картинки — WebP в `assets/images/` (папку `images/` удалили как дубль).
- Анимации только transform/opacity.
- v1: заголовки режет `js/kinetic.js` на буквы — буквы обязаны лежать внутри `.kin-word` (nowrap), иначе слова рвутся.
- Факты о Рафаэле и людях — только из `research/RAFAEL_2026-10-12.md` или от заказчика. Ничего не дописывать «для красоты».
- Тексты: без антитез, без инфобиз-лексики («коуч», «наставник», «успешный успех»).

## 4а. Бэкапы версий и работа рядом с Codex
- **Каждая версия = замороженная копия** в `versions/<id>/` (свои css/js, общие assets). Список всех — `versions/index.html`.
  Создать: `python3 tools/snapshot.py dir <папка> <id> "<название>" "<описание>"`. Снимки НЕ редактируются — изменения только новой версией.
  После каждого крупного изменения дизайна — новый снимок ДО следующих правок (чтобы можно было откатиться, даже если заказчик не сможет объяснить словами, «как было»).
- **Codex** работает на той же ветке в папке `codex/` (бриф — `CODEX_BRIEF.md`). Claude не трогает `codex/`, Codex не трогает папки Claude. `assets/` — только добавлять.
  Перед push всегда `git pull --rebase origin claude/peaceful-allen-zumohw`. Коммиты Codex — с префиксом `[codex]`.
- Новые версии Claude делать в новой папке (например `d/`), а не поверх выбранной — старая остаётся живой.

## 5. Решения заказчика (фиксировано)
- **Название клуба — Business Syndicate** (переименован из «Связи Решают»). Логотип новый — файл запросить у заказчика.
- **«Связи решают»** — только фраза-крючок, не название и не главный слоган.
- **«45 млн ₽ инвестиций» — УБРАНО** (не подтверждено).
- **Кодекс** — 8 правил в v1 оформлены нормально, содержание не трогаем: это негласный свод «как вести себя достойно».
- Продукт — подписка 10/30/50 тыс. ₽/мес, мастермайнд входит. Ближайшая встреча 1 ноября 2026.
- **Дизайн v2 «бумага + засечки» отвергнут** («кремовая подложка, старо, дёшево, осени не видно»). Нужен современный премиальный дизайн с ВИДИМОЙ сезонностью. Перед внедрением показывать заказчику варианты на выбор.
- Продажи: **подписка со скидкой** (персональная скидка, 48 часов подумать, рассрочка). Гостевой вход — пока не решено. Подробно — `SALES.md`.
- Рыжий цвет заказчику не нравится в больших количествах.
- **Новое направление (13.10):** много воздуха; телефон — как презентация Apple (вертикальные полноэкранные слайды); компьютер — своя раскладка; сильный продающий e-commerce. Референсы — доска Pinterest заказчика + сайт YOLO Welcome (`research/MOODBOARD_2026-10-13.md`). v3 A/B/C: «похоже на стрёмный лендинг».
